# CyberBLADE Closed-Beta Deployment Runbook (Vercel + Hosted Supabase)

**Platform Target:** Vercel (Serverless Next.js App Router, Node >= 24, Region `bom1` / Mumbai) + Hosted Supabase (PostgreSQL 15+ with pg_crypto & uuid-ossp).  
**Scope:** Invite-only closed beta (20–100 learners).  
**Standing Rule Compliance:** Additive migrations only; fail-closed security; zero client oracles; 100% Row Level Security (RLS) enforcement; zero build warnings; no test data seeded to learner-facing tables.

## 1. Complete Environment Variables Specification

Every variable is validated at server boot via `lib/config/runtime-config.ts` (`assertRuntimeConfig()`), `lib/config/env.ts` (`assertEnv()`), and `lib/supabase/config.ts` (`assertSafeStorageMode()`). If required variables are missing or hold placeholder strings (e.g. `your-project`, `changeme`, `dummy`), the production deployment **refuses to boot (fails closed)**.

Client bundles are scanned at build time by `scripts/scan-client-bundle.mts` (`npm run scan:bundle`) to guarantee that server-only keys never leak to client JavaScript chunks.

## 2. Serverless Build Configuration

Next.js Turbopack compiles serverless lambdas for App Router routes. In serverless environments, static files (YAML curriculums, scenario seeds, exam banks, and rubrics) located in `content/` are bundled directly into function outputs:

1. **`next.config.ts` Tracing:**
   ```typescript
   outputFileTracingIncludes: {
     "/**/*": ["./content/**/*"],
   }
   ```
   Ensures every App Router route and Server Action has full filesystem read access to `content/` (`process.cwd() + "/content/..."`).
2. **Build Warning Free:**
   Dynamic `import.meta.url` and Turbopack path-tracing issues in `shift-composer.ts` have been bounded with `/*turbopackIgnore: true*/`. `npm run build` generates **0 warnings** across all 29 static routes and API endpoints.
3. **Fail-Closed Storage Mode:**
   If `NODE_ENV === "production"` or `VERCEL === "1"` without configured `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `assertSafeStorageMode()` throws a fatal error at boot. No route falls back to local JSON files in production.

## 5. Security Hardening & Rate Limits

1. **Content Security Policy (CSP):**
   - In production: Strict CSP without `unsafe-eval`.
   - `default-src 'self'`; `script-src 'self' 'unsafe-inline'`; `style-src 'self' 'unsafe-inline'`; `img-src 'self' data: blob:`; `connect-src 'self' <supabaseOrigin>`; `object-src 'none'`; `base-uri 'self'`; `form-action 'self'`.
2. **Security Headers:**
   - `X-Content-Type-Options: nosniff`
   - `X-Frame-Options: SAMEORIGIN` (and `frame-ancestors 'self'`)
   - `Referrer-Policy: strict-origin-when-cross-origin`
   - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
   - `Cross-Origin-Opener-Policy: same-origin`
   - `Cross-Origin-Resource-Policy: same-origin`
   - `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` (enforced on HTTPS)
3. **Closed Beta Access Gate:**
   - `BETA_INVITE_ONLY=true`: Requires a valid invite code created via `npm run beta:invites -- create --label <org> --max 10`.
   - Code redemption runs atomically in Postgres (`beta_redeem_invite`); invalid or exhausted codes return uniform timing errors.
4. **Search Engine Shielding:**
   - `X-Robots-Tag: noindex, nofollow` on all responses while beta is active.
   - `robots.txt` disallows all crawlers (`Disallow: /`).
5. **Rate Limiting Matrix (PostgreSQL Stored Procedure `rate_limit_hit`):**
   - Magic link / Auth: 5 attempts/min per IP, 3 attempts/min per email.
   - Beta invite redemption: 10 attempts/10 min per IP, 300 global/10 min.
   - The Handler (AI): 30 req/min per IP, 50 req/day per learner, 50,000 tokens/day per learner, $10.00/day global ceiling.
   - Exam & lab submissions: 5 submits/60s per learner, 60 answers/min per learner.
   - Feedback: 10 submissions/hour per learner.

## 6. Observability & Monitoring

1. **Error Tracking:**
   - Compatible with Sentry Free Tier via `ERROR_REPORTER_DSN`.
   - When set, errors captured in `instrumentation.ts` (`onRequestError`) are scrubbed of all PII, learner text, cookies, and tokens before transmission.
   - If `ERROR_REPORTER_DSN` is empty, errors fall back cleanly to structured stdout JSON logs with unique request digest.
2. **Structured Server Logs:**
   - Request IDs attached to every HTTP request (`x-request-id`).
   - PII scrubbing via `lib/observability/redact.ts` redacts passwords, tokens, API keys, email addresses, and IPs.
3. **Health & Readiness Endpoints:**
   - `/api/health`: Cheap liveness check (answers 200 `{ status: "ok" }` even during maintenance mode).
   - `/api/ready`: Readiness probe verifying rate-limiter and database connectivity (answers 200 or 503 if limiter down).
4. **In-App Feedback & Bug Reports:**
   - "Report a problem" widget in app shell (`FeedbackDialog.tsx`) and context links on lessons/labs.
   - Submissions are validated and stored directly to `learner_feedback` table in Supabase.
   - Export reports using `npm run beta:feedback`.

## 7. Vercel Configuration & Function Settings

Configured in `vercel.json`:
```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "regions": ["bom1"],
  "functions": {
    "app/**/*": {
      "maxDuration": 60
    }
  },
  "crons": [
    { "path": "/api/cron/cleanup", "schedule": "15 3 * * *" },
    { "path": "/api/cron/ai-grading", "schedule": "45 3 * * *" }
  ]
}
```
- **Region:** `bom1` (Mumbai, India) minimizes network latency for learners in India and Southeast Asia.
- **Node.js Runtime:** Node 24.x (configured via `"engines": { "node": ">=24.0.0" }` in `package.json`).
- **Function Timeout:** `maxDuration: 60` allows ample time for multi-stage exam submissions, rubric grading, and AI Socratic tutor streams without gateway timeouts.
- **Static Asset Caching:** Next.js automatically outputs immutable cache headers for `/_next/static/*` (`Cache-Control: public, max-age=31536000, immutable`). Sensitive learner endpoints explicitly set `Cache-Control: private, no-cache, no-store, must-revalidate`.

## 9. Rollback Runbook & Emergency Switches

1. **Instant Maintenance Mode (Traffic Pause):**
   - In Vercel Dashboard → Environment Variables, set `MAINTENANCE_MODE=true`.
   - Redeploy or trigger an instant rollback.
   - All inbound traffic immediately receives HTTP 503 with `Retry-After: 600`. `/api/health` remains responsive for uptime monitors.
2. **AI Provider Kill Switch (Cost Protection):**
   - If AI spend spikes or anomalies occur:
     - Set `SOC_AI_GRADING_KILL_SWITCH=1`
     - Set `HANDLER_MAX_GLOBAL_DAILY_BUDGET_USD=0.01`
   - AI endpoints instantly drop all outbound LLM calls and fall back to local deterministic guidance.
3. **Vercel Instant Rollback:**
   - In Vercel Dashboard → Deployments, find the previous stable deployment and click **"Instant Rollback"**.
   - Vercel switches edge routing within seconds without rebuilding.
4. **Database Rollback:**
   - Each migration file in `supabase/migrations/` contains specific rollback SQL statements in its header comments.
   - If a schema defect is detected, apply the corresponding down-migration script or restore the pre-migration snapshot using `npm run db:restore-check`.

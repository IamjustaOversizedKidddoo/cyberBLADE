> **Outcome:** you can recognise the network shapes of command and control, scanning and data theft, and tell them apart from the ordinary software that looks similar.

## Why this matters on shift

Attackers can hide what they send, but they find it much harder to hide *how* they send it. Malware that checks in every minute, a laptop that knocks on every machine in the office, or a server that suddenly sends gigabytes out at night all leave shapes in network data. Those shapes are some of the most reliable clues you have, as long as you also know which normal software makes the same shapes.

## Core ideas

### Beaconing

**Beaconing** is a program contacting the same destination at regular intervals, usually to check for instructions. Command and control channels often beacon.

Think of a night guard who rings the control room every hour on the hour to say "all fine". The calls are short, regular and always to the same number. If you saw those calls on a phone bill, you could guess the pattern without hearing a word.

Beaconing shapes in flow records:

- The same source and destination, again and again, often for hours or days.
- A steady interval, such as every 60 seconds.
- Small, similar sizes for each connection.

Malware authors often add **jitter**: a random variation in the interval (for example 60 seconds plus or minus 20%) to make the pattern harder to spot. Regularity is still visible over many connections.

Many legitimate programs beacon too: update checkers, antivirus and endpoint agents, chat and mail clients, time synchronisation and monitoring tools. Before you call it command and control, check the destination: is it a known service for software installed on that machine? The simulator's flow view includes a periodicity check that reports whether a regular interval was detected, its length and a confidence. Treat it as a pointer, not a verdict.

### Scanning

A **port scan** is a series of connection attempts to find which hosts are up and which services they run (ATT&CK T1046, Network Service Discovery, when done from inside). Two shapes:

- **Horizontal:** one port on many hosts. Someone is looking for every machine that runs a particular service.
- **Vertical:** many ports on one host. Someone is mapping what a single machine offers.

In flows, scans look like many short, incomplete connections (SYN only, little or no data back). From the internet, scans of your public addresses happen constantly and are mostly background noise. From an internal workstation, scanning is much more interesting: it suggests discovery after a compromise, unless it is an approved scanner.

### Unusual egress

**Egress** is traffic leaving your network for the outside. Data theft is egress, so the questions are about change from normal:

- **Volume:** far more sent than this host usually sends.
- **Destination:** a new destination, a personal cloud storage service, or a destination in no business relationship.
- **Time:** large uploads at night or at weekends for a host that is normally quiet then.
- **Channel:** an unusual protocol or port for this host.

The **baseline** is the normal pattern for a host or account, against which unusual activity is compared. A file server sending 5 GB a night to the backup service is normal; a reception PC sending 5 GB anywhere is not.

Attackers often exfiltrate over channels that already exist: their command and control channel (T1041) or common web services such as cloud storage (T1567), precisely because those blend in.

## Worked example

The flow view flags periodic traffic from two Larkspur Freight workstations:

<LogBlock
  title="Periodicity findings (synthetic)"
  lines={[
    "ws-140  -> 192.0.2.198:443   interval 3600 s   confidence 97   bytes per connection 1.1-1.3 KB",
    "ws-226  -> 192.0.2.199:443   interval   60 s   confidence 71   bytes per connection 0.4-0.6 KB",
  ]}
/>

**A false lead.** ws-140's pattern is the most regular, with 97% confidence. But the destination resolves to the update service of the PDF reader installed on every Larkspur laptop, and the hourly check matches that product's update schedule. It is ordinary software beaconing. The analyst notes it and moves on.

**The real one.** ws-226 contacts 192.0.2.199 every 60 seconds with some jitter, which is why the confidence is lower. Passive DNS shows the address used only by a domain first seen three days ago. No installed software on ws-226 explains it. The connections have run since 06:10 UTC, and at 06:42 one connection sent 85 MB instead of the usual half a kilobyte.

**Decision.** A jittered one-minute beacon to a three-day-old domain, followed by one large upload over the same channel, fits command and control with exfiltration over the C2 channel (T1071, T1041). The analyst escalates ws-226 with both findings, and notes ws-140 as checked and benign.

## Common mistakes

- **Calling every regular connection command and control.** Update checkers and agents beacon all day.
- **Dismissing a beacon because the interval varies.** Jitter is deliberate.
- **Escalating internet-wide scans of your public addresses.** They are constant background noise unless something answered that should not.
- **Ignoring scans from inside.** Internal scanning by a workstation is a discovery warning sign.
- **Judging volume without a baseline.** Large is relative to what that host normally does.

## What good looks like

A strong analyst names the shape (beacon, scan, unusual egress), checks the boring explanations against the asset and software lists, uses each host's baseline, and links shapes together, such as a beacon followed by a large upload on the same channel.

## In the real world

Network monitoring tools, SIEM analytics and endpoint tools offer beacon detection, scan detection and volume anomaly alerts. They all produce false positives from legitimate software, so most teams keep allow-lists of known update and agent destinations. Exfiltration to cloud storage is hard to spot because legitimate staff use those services too; endpoint evidence about which process sent the data often settles it.

## Remember it like this

Regular and small is a beacon, many and failed is a scan, big and out of pattern is egress: then find the boring explanation or rule it out.

## Interview answer

"Beaconing shows as regular, small connections to the same destination, often with jitter, so I check whether it's known software like an updater before calling it command and control. Scanning shows as many short, incomplete connections, either one port across many hosts or many ports on one host; internal scanning from a workstation worries me far more than internet noise. For exfiltration I compare outbound volume, destination, time and channel against the host's baseline, and I look for links, such as a beacon followed by a large upload."
